# Project vision

## Purpose

FitSpace helps homeowners, renters, designers, retailers, and staging professionals explore how furniture looks and occupies space before purchase. The promise is useful visualization supported by transparent measurements, not a guarantee of fit from incomplete evidence.

**Tagline:** See it. Place it. Know it fits.

## Initial MVP: Phases 1–5

A visitor can explore an interactive room, open a guest workspace, enter rectangular-room dimensions, add clearly labeled sample furniture, move/rotate it, compare materials, inspect spatial warnings, and recover a local design. With an account, they can save, reopen, and share a read-only design securely. This is the first useful product milestone; it is not the complete commercial release.

MVP includes metric/imperial controls, undo/redo, perspective/overhead views, dimension provenance, conservative overlap/clearance checks, and accessible numeric alternatives to dragging. No purchases occur inside FitSpace.

Phases 6–9 complete the requested launch scope: calibrated photo reference, device-supported AR, constrained AI assistance, retailer integrations, billing, and production hardening. Multi-room reconstruction, collaboration, advanced delivery-path planning, and advanced light simulation are post-launch.

## Primary journeys

1. **Guest:** landing → Start Designing → room preset or measured rectangle → catalog → place/rotate furniture → inspect dimensions and warnings → recover after refresh. Local save is explicitly distinct from cloud save.
2. **Account owner:** guest design → sign in → explicitly import into an owned project → autosave → reopen → duplicate/rename → create/revoke a read-only share. Signing out clears private client caches; cloud errors never appear as successful saves.
3. **Viewer:** open share link → inspect the shared snapshot → no mutations or access to unrelated projects. Revocation disables future access.
4. **Real-space preview (later):** photo + known measurements → manually calibrated approximation, or compatible product → supported AR viewer → return to design. Unsupported devices receive an honest fallback.
5. **Retailer (later):** licensed model + verified dimensions → validated catalog entry → preview/embed → authentic retailer product link. Demo objects never masquerade as purchasable real products.

## Visual direction

Use the supplied images as design references, not licensed downloadable assets. Combine the focused scene/inspector composition of architectural software with warm wood, stone, textiles, off-white surfaces, charcoal typography, and restrained accents. The photographic reference sets an aspirational material/lighting direction; initial procedural geometry must not be described as photorealistic capture.

Desktop: project toolbar, left catalog/hierarchy, central viewport, right contextual inspector. Tablet/mobile: prioritize viewport and a single task drawer; retain accessible numeric editing and touch-friendly targets. Avoid rendering desktop panels at unreadable mobile sizes.

The landing page introduces the live room, functioning before/after comparison, features, process, example designs, and a truthful business offering. Pricing appears when subscriptions exist. Future features must be labeled as planned and must not have fake working controls.

## Success criteria

- A first-time guest can create a measured room and place furniture without signup.
- Entered dimensions and saved transforms round-trip without unit drift.
- Spatial feedback names its assumptions and missing measurements.
- Core controls work with keyboard and numeric inputs, not only pointer gestures.
- Cloud data remains private except for intentionally shared snapshots.
- Representative journeys, performance budgets, browser behavior, and access controls pass the gates in the roadmap before readiness claims.
